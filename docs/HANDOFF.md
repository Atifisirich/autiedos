## 1. What this is

A staff-only school operating system (PRD: 32 pages) for CBSE / Cambridge schools: tasks, attendance, leave, approvals,
timetable and substitution, AI lesson planning, exams, observation, helpdesk, circulars, reports, in English, Hindi and Telugu.
Stack: Next.js 15 (web, `/os`), Expo (mobile), Supabase Postgres (Mumbai), pnpm monorepo.

Hard rules from the PRD (do not break these):
1. Schema changes by migrations only (`supabase/migrations`). 2. RLS on every table, with an RLS test.
3. Nothing about a school's structure is hard-coded; it is configuration data. 4. No literal strings in components; all text is an i18n key
(en/hi/te). 5. AI only on the server, every call recorded in `ai_generations` and `ai_credit_ledger`. 6. Never send student names,
phones or staff personal data to AI. 7. Every state change audited (`audit_log`). 8. One shared API and validation (`packages/shared`)
for web and mobile. 9. Module flags per branch. 10. Record ambiguity decisions in `docs/DECISIONS.md`; append to `docs/BUILD-LOG.md` after each phase.

## 2. Repository map

```
apps/web            Next.js app. app/os/** screens, app/api/os/[...path] (API wrapper), app/api/cron/tick, lib/, components/, e2e/smoke.mjs
mobile              Expo 52 + expo-router. app/(tabs)/*, src/{api,outbox,session,push,ui,useLoad,config,storage}.ts(x)
packages/shared     zod schemas, rules engines (rules/*), timetable generator, lesson plan schema, presets, i18n (index.ts + source/*.txt + built json)
packages/server     api/index.ts (route table + dispatch), services/*, adapters/{ai,mockAi,channels}, auth, scheduler, notify, jobs, seed/, test/
supabase            migrations/ (6 files, 128 tables), local/shim.sql (emulates auth/storage/roles for plain Postgres)
kb                  Help-bot articles: 39 slugs x en/hi/te (generated by scripts/kb-source.py)
scripts             db.mjs (reset|migrate|status), build-i18n.mjs, check-i18n.mjs, kb-source.py
docs                PRD, AUDIT, DECISIONS, BUILD-LOG, HANDOFF
```

Key server concepts:
* `run(ctx, (c, sys) => ...)` runs one transaction as the signed-in user (RLS applies: sets `request.jwt.claims`, `set local role authenticated`).
  `sys(() => ...)` temporarily resets the role for checked side effects (notifications, system writes). `asService` is for jobs.
* Permissions: `has_permission(user, module, action, target)` with scopes own/team/department/wing/branch/group. In code: `need`, `needModule`, `rank`.
* Auth: Supabase OTP -> `POST /auth/session` -> HS256 session token (`AUTH_JWT_SECRET`), per-device revocable. `AUTH_PROVIDER=dev` enables email-only login for demos/tests.
* Jobs: `jobs` table driven by `/api/cron/tick` (Vercel cron every minute, `CRON_SECRET`); handlers in `scheduler.ts`.
* AI: `adapters/ai.ts` (Anthropic SDK, JSON-schema output, validate + repair, up to 3 attempts, cost only on success), `mockAi.ts` when no key.
  Models are rows in `platform_settings` (strong `claude-opus-5-5`, fast `claude-haiku-5-5`), credit costs in `ai_action_costs`.
* Translations: edit `packages/shared/src/i18n/source/*.txt` (`key | English | Hindi | Telugu`), run `pnpm i18n:build`, then `pnpm lint`.

## 5. Gotchas learned the hard way

* Postgres for local dev lives outside the repo (we used `/tmp/pgdata`, port 54322, trust auth). If the machine restarts it must be started again
  (`pg_ctl -D <dir> -o '-p 54322 -k /tmp' start`, remove stale `postmaster.pid`). Data is lost if the directory is lost; `pnpm db:reset` rebuilds it.
* Seed titles of notifications are stored translated at seed time: run `pnpm i18n:build` **before** `pnpm db:reset`, or inbox items show raw keys.
* `useEffect` callbacks must not return non-functions (`cond && setState()` crashes React 19). Language is applied after mount to avoid hydration errors.
* After `next dev`, always `rm -rf apps/web/.next` before `next build`/`start`, and kill by `pkill -f next-server` (plain `pkill "next start"` misses it).
* One `@types/react` (19.0.2) is forced by `pnpm.overrides` so web and mobile typecheck together; mobile runtime React is 18.3.1 (Expo 52).
* `flows.test.ts` and the seed both use the real current date. Do not hard-code dates in tests.
* When adding a SQL select for a lookup, check the column exists on that table (a wrong column broke every form once).
* Anything added to the UI needs keys in all three languages; the check script will fail otherwise.
